Lightspeed v0.3.0 introduces a unified resource attachment model and moves session preparation into durable workflows. It also adds VFS–environment transfers, environment skill discovery, and native image/PDF content from tools and sub-agents.

**Breaking changes and upgrade requirements**

- This is a coordinated breaking release. Session configuration, stored `ConfigChanged` events, and session workflow payloads change without compatibility aliases. Existing session histories and continuation payloads are unsupported; restarting workers does not migrate them. Plan a maintenance window and create fresh sessions and session workflow histories after upgrading.
- Resource configuration now uses explicit attachments: `vfs.workspaces` with `read`/`edit` access, `environments.environments` with per-machine `read`/`edit`/`exec`/`jobs` grants, MCP server attachments with optional tool subsets, and sub-agent profile attachments. Environment provider/registration-key filters and the previous session-wide tool grants are replaced by attachment membership and access. Update API callers, saved profiles, bot configuration overrides, and other persisted configuration documents to the new generated contract.
- Profiles no longer provision environments or carry a separate existing-environment selection. Session creation no longer accepts an environment override. Provision environments independently and attach them through configuration; an attachment can supply the default selection. Closing a session no longer closes an environment.
- Before shutting down the old runtime, quiesce ingress and scheduled work, finish or cancel active runs, and close sessions being retired. Preserve a coordinated recovery set of PostgreSQL, Temporal, object storage, configuration, keys, and machine state. Retained old session documents are not automatically converted or guaranteed readable by the new runtime; preserve a compatible recovery copy for historical access.
- Apply runtime schema migration 10 with the new `lightspeed-server migrate`, then deploy matching runtime, Platform, connectors, Configurator, CLI, and client artifacts. Migration 10 removes environment session-origin columns while retaining environment resources. It does not rewrite saved profiles or migrate workflow histories. Platform remains at schema revision 1. There is no automated in-place conversion of old session/configuration state in this release.
- Update installed environment daemons to the matching release for the new transfer and scan capabilities. Environment protocol 2 remains unchanged, so protocol-mismatch automatic upgrade will not install v0.3.0 merely because its product version is newer. The API protocol identifier remains `lightspeed.agent.api.v1`; it is not a guarantee that v0.2 configuration shapes remain compatible. Use the client and contracts from this release.

See [Upgrades and recovery](https://ls.bot/docs/deployment/upgrades-and-recovery/) for recovery planning and the release-specific procedure.

**Durable session preparation and resource access**

- Session workflows own preparation and configuration reconciliation. Context refresh happens at workflow admission, keeping prompt and catalog observations stable within a run and avoiding duplicate gateway discovery.
- Explicit environment attachments define the allowed machines and each machine's access and working directory. Selection validates membership and registry state; actual use handles readiness and waking. VFS workspaces and environment filesystems retain independent working directories and access boundaries.
- Filesystem prompt sources read direct `.md` and `.txt` files in filename order. Skill catalogs support conventional installer roots and explicit overrides; roots resolve against the relevant filesystem's working directory.

**Transfers, skills, and tool media**

- Materialize VFS files or trees into environments and capture environment content back into VFS on Linux and macOS. Transfers use bounded streaming, whole-file reuse, and atomic replacement while respecting attachment grants.
- Environment skill discovery uses shared scans and a common catalog API shape. Discovery refreshes at idle boundaries; ordinary edits and tool calls within a run do not repeatedly rebuild catalogs.
- Images and PDFs returned by MCP tools, read from files, or returned by sub-agents reach models natively through stable media handles. Provider lowering, storage, and transcript projections retain the content and its provenance.
- Environment filesystem and process operations use portable Rustix implementations. Transcript, mobile UI, resource editors, and demo fixtures reflect the new capabilities and attachment model.

**Release preparation**

- `npm run release:prepare -- 0.3.0` updates the product metadata, shared Rust workspace version, and Cargo lockfile together. Released Rust packages inherit that version; npm versions are assigned during release staging.
- Release verification checks inherited package versions and lockfile consistency. Tagged publication accepts stable versions only, preventing a prerelease from accidentally becoming npm's `latest`.
